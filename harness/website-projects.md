# ハーネス: ウェブサイト制作案件のルール

`knowledge/web-side-business.md` の方針に基づき、この副業向けにサイトを作る際は以下を守る。

## 技術方針

- 静的 HTML/CSS/JS を基本とする（フレームワーク・ビルド工程は要件が明確に必要になるまで導入しない）。
- レスポンシブ必須。スマホ表示を最優先で確認する。
- 外部サービス（フォーム送信、予約システムなど）を使う場合のみ、必要最小限で依存を追加する。
- 個人情報（本名・実メールアドレス等）をプレースホルダーとして無断で実データに置き換えない。
  ダミー値（`contact@example.com` 等）は依頼者本人の確認を経てから差し替える。

## ディレクトリ規約

- 各案件・成果物は `projects/<案件名>/` にまとめる。
- 自社ポートフォリオは `projects/portfolio-site/`。

## 出力の質

- 実在しない実績を「実績」と偽らない。サンプル・想定案である場合は明記する（例: SAMPLEタグ）。
- 料金や納期は目安である旨を明記し、断定的な確約をしない。

## 画像素材

- 写真は商用利用・改変可でクレジット表記が不要なライセンス（Unsplash License / Pexels License / CC0 等）のものだけを使う。
- 外部URLへのホットリンクはせず、ダウンロードして各サイトの `images/` に置く。出典URLは `images/SOURCES.txt` に残す。
- 実在の施設・看板・ブランドロゴ・商標が写っている写真は、架空の事業者サンプルには使わない。
- 表示サイズに合わせて縮小する（1枚あたり目安 50〜200KB。Unsplash は CDN の `?w=800&q=68&fm=jpg` 指定で縮小できる）。
- CSSのプレースホルダーを置き換えるときは、元の配色に合わせた半透明グラデーションを重ねて `background-image` にすると世界観を保ちやすい。
- クラウド環境での取得: Unsplash は WebFetch で検索ページから写真IDを取得し、`images.unsplash.com` からダウンロードできる（unsplash.com 本体を curl で開くとボット対策に阻まれる）。Pexels / Pixabay / Wikimedia は環境のネットワークポリシーでブロックされることがある。
- 画像の重複禁止: 使用した写真IDを台帳（1行1ID）に記録し、取得前に照合する。同じ撮影の別カット（同一人物・同一テーブルなど）も重複扱いにする。サイト内での同一写真の使い回しも避ける。
- 人物写真は「日本人と思える」東アジア系のみ。該当写真が見つからない役（医師・スタッフ等）は、顔の写らない手元写真・空間写真・アバター表現で代替する。
- 服のロゴ・看板の文字・商品ラベルが写る写真は、トリミング（Unsplash CDN の `&fit=crop&crop=focalpoint&fp-y=`）で外すか不採用にする。
- 実在地名の番地（例: 羽田3-4-2）や実在の地図埋め込みは使わず、「架空県〇〇町」または地域名＋架空の町名にし、地図はCSSで描いた架空マップにする。

## 検証

- 公開前に 1280px / 390px の全ページスクリーンショットを撮って目視確認する（Playwright。`.reveal` はスクロール後に `is-visible` を付与して撮る）。
- このクラウド環境では Google Fonts が読み込めず、縦書き見出しの漢字がフォールバック（WenQuanYi）で重なって表示されることがある。環境依存の表示崩れなので、`IPAGothic` 等で指定し直して配置が正しいかを確認する。本番用CSSにはヒラギノ明朝・游明朝をフォールバックに入れておく。

## ROOTPAGE本体の改修ルール（2026-09 追記）
- 本体（rootpage-site）の master へのpushは即本番反映。大きな改修は別ブランチ（例: redesign/xxx）でpushし、Vercelのプレビュー（`rootpage-site-git-<branch>-makrh11web-1041.vercel.app`）でユーザー確認→OK後にmasterへマージする。
- 「テンプレっぽい」と言われないために、ヘッダー形式・メイン体験・レイアウト文法の3点をサイトごとに変える（共通ヘッダー＋写真ヒーロー＋カードグリッドの繰り返しを避ける）。
- WORKS配列（js/main.js）は本体のサンプル一覧・トップ表示の唯一のデータ源。業種の大分類は同ファイルの CATEGORIES で管理し、新しい業種を追加したら CATEGORIES にも追記する。
- 画像モザイクは grid-auto-flow: dense だけだと末尾に隙間が出る。大きいタイルの位置を固定（grid-area）して、セル数が列数で割り切れるように設計する。
- ブランチへのpush後にVercelのプレビューが自動で作られないことがある。その場合は Vercel MCP の create_deployment（gitSource: github / org / repo / ref / sha、target指定なし＝プレビュー）で手動作成する。target に production を指定しないこと。
- デザインの「なんか違う」への対処チェックリスト：①差し色の使いすぎ（ボタンと最重要の数字だけに絞る）②全セクション同じ見出しの型（英字ラベル＋大見出しの繰り返しはテンプレ感の元）③見出しが全部極太で叫んでいる ④汎用の素材写真 ⑤余白が広すぎて間延び。
- 本番に反映する前に、検索対策（noindex）が meta・robots.txt・レスポンスヘッダーのどこで効いているかを確認する。Vercel のプレビューURLは自動で noindex ヘッダーが付くが、本番URLには付かない。
- ユーザーに共有する本番URLは必ず `https://rootpage-site.vercel.app/`。`rootpage-site-makrh11web-1041.vercel.app` や `-git-` 付きのURL、個別デプロイのURLは Vercel の保護（Standard Protection）でログインが必要になり、一般の人は見られない。
- 「いろいろなサイトが作れると思わせたい」依頼（2026-09 LP5＋HP5）では、サイトごとに①配色②フォント組み合わせ③ヘッダー形式（ヘッダーなし／電話バー／カート／縦レール／タブ／サイドバー／中央ロゴ／メガメニュー／吹き出しナビ等）④メイン体験（シミュレーター・診断・カート・すごろく・予約表・絞り込み・ウィザード等）⑤レイアウト文法をすべて変え、共通JS・共通CSSは使わない。事前に10サイト分の組み合わせ表を作って重複を避けるとぶれない。
- 画像出典は各サイトの `images/SOURCES.txt` に置く（サイト直下ではない）。get.sh が書き出す `images/.src` を最後に SOURCES.txt へ変換して `.src` は削除する。
- ブランドロゴ・社名・ゲーム機など第三者の商標が写った写真は避けるか、object-position でトリミングして見えないようにする。
- 「こういうのも作れる」アピール用の追加（2026-09）では、店舗系以外の型を混ぜると幅が伝わる：イベントLP（カウントダウン・タイムテーブル）、SaaSのLP（写真を使わずUIをHTML/CSSで再現）、美術館の企画展（縦スクロールで横に流れるギャラリー）、自治体の移住ポータル（地図・診断・物件検索）など。
- 写真を使わないサイト（SaaS等）のWORKSサムネイルは、Playwrightでページのファーストビューを1280×800のJPEGで撮って images/hero.jpg にする。
- スクショ確認時の注意：`html { scroll-behavior: smooth }` のページは clk.js のスクロールが追いつかず、IntersectionObserver の表示アニメーションが発火しないまま撮れることがある（本番では問題なし）。確認時は表示用クラス（is-in 等）をJSで付けてから撮る。ビューポートだけ撮るときは scratchpad の vp.js を使う。
- 写真の看板・店名チェック：夜の商店街や店先の写真は看板の文字が読めることが多い。実在の店名に見える文字が写っていたら差し替える。
