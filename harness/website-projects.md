# ハーネス: ウェブサイト制作案件のルール

`knowledge/web-side-business.md` の方針に基づき、この副業向けにサイトを作る際は以下を守る。

## 技術方針

- 静的 HTML/CSS/JS を基本とする（フレームワーク・ビルド工程は要件が明確に必要になるまで導入しない）。
- レスポンシブ必須。スマホ表示を最優先で確認する。
- 外部サービス（フォーム送信、予約システムなど）を使う場合のみ、必要最小限で依存を追加する。
- 個人情報（本名・実メールアドレス等）をプレースホルダーとして無断で実データに置き換えない。
  ダミー値（`contact@example.com` 等）は依頼者本人の確認を経てから差し替える。

## ディレクトリ規約

- 各案件・成果物は `projects/<案件名>/` にまとめる。
- 自社ポートフォリオは `projects/portfolio-site/`。
- 業種別サンプルは `projects/sample-<業種>/`（例: `sample-beauty-salon`, `sample-manufacturing`）。
  - 1ページ完結のLP想定（個人店向けなど）は Artifact断片形式（`<title>`から始まり`<html>/<head>/<body>`タグを持たない）でもよい。
  - 多ページ構成のHP想定（法人・中小企業向けなど）は通常の完全なHTMLドキュメント
    （`<!doctype html><html lang="ja"><head>...</head><body>...</body></html>`）で各ページを作成し、
    共通CSSは `assets/style.css`、共通JSは `assets/main.js` に外部化して全ページから相対パスで読み込む。
    ヘッダーの共通ナビゲーション（`aria-current="page"`で現在地表示）とフッターは全ページで揃える。

## リサーチ方針（参考サイトの調査）

- サイトの構成・デザインの方向性を検討する際は、SANKOU!(sankoudesign.com)のような業種別Webデザイン
  ギャラリーサイトで同業種・類似業種の実例を確認し、複数サイトの傾向から「この業種で好まれる構成・トーン」
  を抽出してから、オリジナルの構成案を設計する。特定サイトのデザイン・文章・画像・レイアウトの丸パクリは禁止。
- **重要な制約**: このセッションの実行環境ではWebFetchによる外部サイトへの直接アクセスがネットワーク
  ポリシーでほぼ全てブロックされている（sankoudesign.comはもちろん、example.comのような一般的な
  ドメインでも403でブロックされることを確認済み）。そのため参考サイトの直接閲覧はできない前提で、
  WebSearchツール（複数クエリでの検索結果スニペット・要約）を使って業種ごとの一般的な構成要素・トーン・
  よくあるページ構成を把握する代替手段を取ること。
- 同様に画像CDN（Unsplash, Pexels, Pixabayなど）へのアクセスも全てブロックされている（403で確認済み）。
  写真素材は使用できないため、CSS/SVGによるオリジナルの抽象的なビジュアル表現（グラデーション、
  幾何学模様、簡易アイコン、図面・路線図風の線画など）で代替する。実在の写真であるかのように偽装しない。

## 多ページサイトの検証（必須）

- 静的サーバー（`python3 -m http.server` 等）でディレクトリを配信し、ヘッドレスChromium
  （`/opt/pw-browsers/chromium-*/chrome-linux/chrome`）またはPlaywright（グローバルインストール済み、
  `/opt/node22/lib/node_modules/playwright`）で全ページをデスクトップ幅・モバイル幅(~390px)の両方で確認する。
  `chrome --headless --screenshot` のCLI単体はモバイル幅でレイアウトが実際と異なる見え方をすることが
  あるため、最終確認はPlaywright経由の実ブラウザ計測（`document.documentElement.scrollWidth` 等）で行う。
- **頻出バグパターン**: CSS Grid/Flexboxのアイテムはデフォルトで `min-width:auto`（内容物の
  最小コンテンツ幅）を持つため、フォームの `<select>` の長い選択肢テキストや2カラムレイアウト内の
  テーブル・入力欄など、縮まない内容物があると、コンテナを `1fr` や `grid-template-columns:1fr` に
  レスポンシブ対応していてもモバイル幅で横スクロールが発生することがある（このプロジェクトで複数回発生）。
  グリッド/フレックスの直接の子要素には基本的に `min-width:0` を明示し、内容物が正しく縮む・折り返す・
  内部スクロールすることを確認する。
- 全ページ間の内部リンク（ヘッダーナビ・フッターのサイトマップ・CTAボタン等）が実際に存在するファイルを
  指しているか確認する。

## 出力の質

- 実在しない実績を「実績」と偽らない。サンプル・想定案である場合は明記する（例: SAMPLEタグ）。
- 料金や納期は目安である旨を明記し、断定的な確約をしない。
